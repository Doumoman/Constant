# SV5 파일 배치와 정리 규칙

사용자가 요청한 전달 방식: ZIP은 유지하고, 복사할 실행 명령은 대화 답변에 직접 제공한다.
별도 사용자 전달용 HANDOFF.md를 만들지 않는다. MCP의 실제 Task/INBOX 문서는 정상 계약대로 유지한다.

## 새 파일의 위치

| 종류 | MapDesign 기준 위치 |
|---|---|
| 입력 원문·manifest·검증기·배포 검사 기록 | MCP/INPUTS/<해당 Task 폴더>/ |
| 다음 실행 인계 | MCP_INBOX/<해당 START>.md |
| 활성 규칙/인덱스 | MCP/SV5/ |
| 실행 산출물·검사·정리 기록 | MCP/GENERATED/<해당 Task>/ |
| Task/Archive/Result/상태 | 실제 MCP 계약이 정한 기존 경로 |
| 이번 작업 임시 자료 | MCP/GENERATED/<해당 Task>/_work/ 안의 명시된 작업 소유 경로 |

Assets/Packages/ProjectSettings가 있는 프로젝트 루트에 Task별 CHECK/FILES/VERIFY/README를 새로 만들지 않는다.
ZIP 압축 해제 시 안의 MapDesign을 프로젝트의 MapDesign과 합친다. 불필요한 이중 Task 폴더를 만들지 않는다.
보조 파일 경로는 서로의 상대 위치/명시한 module root로 찾는다. 작업 디렉터리 변경으로 경로 오류를 숨기지 않는다.
Windows 명령은 python -X utf8를 사용하고 모든 텍스트 입출력 encoding을 명시한다.
manifest는 입력을 검증한다. 정상 실행 증거/현재 상태/commit 검사를 대체하지 않는다.

## 종료 시 정리

이번 작업에서 만든 임시파일의 정확한 목록과 소유를 추적하고 필요가 끝난 것만 Result 작성 전에 삭제한다.
추적되지 않은 폴더 전체를 지우거나 와일드카드로 다른 Task의 파일까지 정리하지 않는다.
원본 입력·SHA manifest·정상 Task/Archive/Result·지속 실행 증거는 정해진 하위 폴더에 보존한다.
검증기와 manifest는 재검증용 보존 자료다. 프로젝트 루트의 매 작업 보조 파일 증가를 막는 것이 이 규칙의 목적이다.
이미 존재하던 예전 패키지 파일은 참조/해시/소유를 조사해 보존 또는 정리 후보로 기록한다.
과거 Task가 위치/SHA를 고정한 파일의 이동은 참조 전환이 필요하다. 이번 임시파일 정리로 묶어 몰래 이동/삭제하지 않는다.
필요한 참조 전환은 별도 명시된 쓰기 범위로 다루며 원본 증거를 보존한다.

## 후속 실행 범위

패키지마다 이 규칙을 반복 복제하기보다 이 활성 문서 경로를 Read에 포함한다.
정상 선행 검증, 허용 Write, 실제 기능 검증과 역할별 SHA 기록은 유지한다.
현재는 한 Task씩 실행하고 종료한다. 여러 Task 묶음 자동 실행으로 전환하는 승인은 아직 없다.
