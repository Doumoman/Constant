# 캐릭터 테스트 규칙

- 각 TASK 문서는 고정된 테스트 개수와 이름을 가진다.
- 테스트 개수를 임의로 줄이거나 이름만 바꿔 통과 처리할 수 없다.
- EditMode는 순수 상태·입력·수치·계약 검증을 담당한다.
- PlayMode는 Rigidbody2D, Collider2D, Tilemap 어댑터, 방 경계와 실제 프레임 진행을 검증한다.
- 테스트용 지형은 생성 결과와 분리된 고정 픽스처를 우선 사용한다.
- 실패 테스트를 Ignore, Explicit 또는 조건부 조기 반환으로 숨기지 않는다.
- 결과 보고서에는 실행 명령, 전체/성공/실패 개수, 실패 이름과 로그 위치를 기록한다.
- 컴파일 오류가 있으면 테스트 미실행이라도 STATUS는 FAIL 또는 BLOCKED다.
