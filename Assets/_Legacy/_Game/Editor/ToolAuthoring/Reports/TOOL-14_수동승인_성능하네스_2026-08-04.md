   - 각 시나리오를 `PASS / FAIL / RESET`으로 기록한다.

2. 동일 랩 씬을 단독 Development Player로 빌드할 수 있는 성능 러너를 추가했다.
   - 1920×1080, 목표 60fps
   - 120프레임 워밍업, 300프레임 측정
   - 현재 방 + 인접 방 프리뷰 구성
   - 방 전환 왕복의 최대 GC Alloc 기록
   - CPU p95, 최대 CPU, 비전환 최소 FPS, 현재 방 일반 AI 수 기록
3. 빌드에서 빠지던 로프 런타임 참조를 수정했다.
   - `RopeAnchorRuntime`, `RopeSegmentRuntime`, `RopeInstallationRuntime`을 각각 동명의 파일로 분리했다.
   - 로프 프리팹 4종을 다시 생성해 모든 `m_Script` GUID를 복구했다.
4. Player의 Frame Timing Stats를 활성화했다.

## 최소 검증 결과

- 기존 EditMode, PlayMode, 500시드 검증은 재실행하지 않았다.
- 스크립트 컴파일 오류: 0.
- Development Player 빌드 1차: 성공, 오류 0.
  - 로프 프리팹의 빌드 누락과 CPU 샘플 미수집을 발견했다.
  - GC 최대 0B, 최소 FPS 58.1.
- 실패 항목 수정 후 Development Player 빌드 2차: 성공, 오류 0.
  - 로프 Missing Script 로그는 제거됐다.
  - CPU 통계가 여전히 0샘플이어서 성능 승인은 보류했다.
  - GC 최대 0B, 최소 FPS 46.2로 비전환 50fps 기준도 이 측정에서는 미달했다.
- 마지막으로 CPU 값이 0일 때 `ProfilerRecorder`로 대체하는 경로와 30프레임 안정화 구간을 추가했으며, 요청한 최소 검증 원칙에 따라 세 번째 빌드는 실행하지 않았다.
