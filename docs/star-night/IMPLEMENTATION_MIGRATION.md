# 《별을 물어오는 밤》 구현 전환 기록

## 이번 전환의 기준

기존 Constant의 핵심은 고정 레시피를 완성해 태그 기반 버프를 얻고, 행성별 자원 게이지를 관리하는 구조였다. 새 방향은 플레이어가 생활 도구의 **동사**를 물체에 적용하고, 그 물리적 결과가 사고·별냄새·마루의 추적·라니의 기록으로 이어지는 시스템 재난형 우주 로그라이크다.

P0는 플레이타임 확장보다 새 핵심 재미가 실제로 순환하는지를 먼저 검증했다.
P1은 그 루프를 다음 챕터로 넘기고, **붉은 실의 장력**과 **선택을 왜곡해 기록하는 라니**를
실제 플레이 규칙으로 추가한다.
P2는 **사라지지 않는 무게**를 세 번째 동사로 추가하고, 공중 물체 우선 추격과 사고 인과 재생으로
마루 디렉터를 확장한다.
P3는 **주소를 붙여 보내기**를 네 번째 동사로 추가하고, 잘못된 배송과 마지막 편지의 처리 방식이
라니와 별길의 상태를 영구적으로 바꾸게 한다.
P4는 **빛으로 깨우고 키우기**를 다섯 번째 동사로 추가하고, 빠른 해결·기다림·과열 수습의 비용을
성장 단계와 정원 열로 동시에 추적한다.

## v0.2 공통 별문 루프 리팩터링

M1-A에서 기존 P0~P4를 비활성화하거나 삭제하지 않고 공통 챕터 루프 어댑터를 추가했다.

- `ChapterLoopDirector`: 도착, 경로 진행, GateReady, GateActive, 방울 1~3, 출항, 휴식 상태를 관리한다.
- `GateContributionInventory`: 일반 가방과 분리된 미장착 별문 기여 물건을 보관한다.
- `GateRouteObjective`: 협력·위험·전용 경로 완료를 별문 기여 물건으로 변환한다.
- `StarGateController`: 서로 다른 경로의 기여를 접수하고 플레이어의 수동 가동을 처리한다.
- `RunRouteMap`: 다섯 별문의 복구 도장과 플레이어·마루 위치를 보존한다.
- `StarNightChapterState`: GateReady와 GateActive, 방울 단계, 출구·유혹 구역 상태를 별도로 보존한다.
- `StarActionRecord`: Route ID, 기여 수, Gate 상태, BellPhase 문맥을 기록한다.

새 공통 루프는 `StarChapterDefinition.useGateLoop`를 켠 챕터에만 적용된다.
확장판 CH1은 M1-B부터 이 경로를 사용하며, 기존 챕터와 레거시 빌더는 기본값 `false`로 기존 플레이를 유지한다.

M1-A 검증 결과는 EditMode `51/51` 통과, C# 컴파일 오류 0이다.

### M1-B · CH1 세 경로와 수동 별문

- 방앗간 수리, 달광산 탐색, 겨울 저장고 차용을 Route A/B/C로 연결했다.
- 세 경로 중 서로 다른 두 개의 길떡만 별문에 장착할 수 있다.
- 겨울 저장고 길떡은 장착 전에 반환할 수 있고, 장착하면 다음 챕터 식량 페널티가 남는다.
- `2/2 GateReady`와 손잡이를 당긴 뒤의 `GateActive`를 분리했다.
- GateActive 이후에만 달배 출구와 달 뒤편 유혹 구역이 함께 열린다.
- HUD, 행동 기록, 라니 결론에 Route·기여·반환·Gate 가동 문맥을 연결했다.
- 확장판 CH1 씬을 재생성해 Route C 반환과 Route A+B 가동 조합을 직접 검증했다.

M1-B 검증 결과는 EditMode `55/55` 통과, C# 컴파일 오류 0, 씬 검증 오류 0이다.

### M1-C · 세 번의 방울과 마루 단계

- GateActive 이후에만 증가하는 별도 `PostGateAlert`를 추가했다.
- 가동 전 별냄새는 기준선으로 저장되고 방울 진행에는 포함되지 않는다.
- Bell 1은 흔적만, Bell 2는 물건·주민 사냥, Bell 3는 플레이어 직접 추격으로 고정했다.
- Bell 2용 주민 표적과 Bell 1~3 환경 시각 효과를 확장판 CH1 씬에 배치했다.
- HUD는 별문 가동 이후 내부 수치 대신 세 개의 방울과 현재 마루 행동을 표시한다.
- Bell 3에서 GateClosing, 카메라 떨림, 닫히는 별문 빛과 간발의 차 출항 플래그가 활성화된다.
- 출항 행동 기록에 최종 Gate/Bell 문맥을 보존한다.
- 레거시 챕터의 기존 냄새 임계치 추격은 그대로 유지한다.

M1-C 검증 결과는 EditMode `60/60` 통과, C# 컴파일 오류 0, 씬 검증 오류 0이다.
직접 플레이에서 선행 냄새 92가 Bell 단계를 건너뛰지 않고, 가동 후 경보 30/60에서
Bell 2의 비플레이어 사냥과 Bell 3의 직접 추격으로 순서대로 전환됨을 확인했다.

다음 단계는 CH1의 목표 이해도와 경로·유혹 선택 체감을 측정하는 M2 플레이테스트다.

### M2 · CH1 내부 플레이테스트 1차

- `ChapterPlaytestTelemetry`가 Route 조합, 주요 상태 도달 시간, 선택 창고, 출항과 강제 귀가를 기록한다.
- 세 Route 역할을 안전·협력 / 위험·탐색 / 빠름·차용으로 UI와 월드에 명시했다.
- 별문 월드 표지가 0/2, 2/2 손잡이, 가동 후 방울 상태로 실시간 전환된다.
- 2/2 토스트와 선택 창고 문구, 세 번째 방울 실패 설명을 가독성 중심으로 조정했다.
- A+B, A+C, B+C 자동 조합과 A+C 실제 씬 스모크를 통과했다.

M2 내부 검증 결과는 EditMode `66/66` 통과, C# 컴파일 오류 0, 씬 검증 오류 0이다.
실제 사람의 이해도와 선택률은 `M2_CH1_PLAYTEST_CHECKLIST.md`의 5세션 표본이 필요하므로
통계형 M2 게이트는 아직 최종 통과로 선언하지 않는다.

### M3-1 · CH2 까치다리 별문 이식

- 기존 제1·제2 닻 물리 퍼즐을 새 닻과 폭풍탑 예비 닻 Route로 연결했다.
- 옛 물류 실 절단을 빠른 전용 Route로 바꾸고 GateReady 전 대체 닻 수습을 추가했다.
- 세 Route 중 서로 다른 닻 2개를 직접 별문에 장착하고 손잡이를 당겨야 출항할 수 있다.
- 해치 선택은 닻 기여와 분리했으며, 직접 해결하지 않으면 별기차 출항이 차단된다.
- 까마득한 별사다리는 GateActive 이후 직접 위험을 선택해야 열리는 유혹 구역으로 바뀌었다.
- 별사다리 진입을 건너뛰고 연결 한도 보상만 획득하는 우회 경로를 차단했다.
- CH2 전용 방울 시각 효과, 주민 표적, 동적 별문 표지와 플레이테스트 계측을 연결했다.

M3-1 내부 검증은 EditMode 테스트 73개 완료·실패 0, C# 컴파일 오류 0,
씬 누락 스크립트 0, 깨진 프리팹 0이다. 실제 씬 A+C 스모크에서 GateReady,
수동 GateActive, 별사다리 직접 선택, Bell 2, 해치 출항 차단과 여행 도장을 확인했다.

### M3-2 · CH4 별 우체국 별문 이식

- 정규 우편, 반송 불가 우편, 마지막 편지 봉인을 Route A/B/C로 연결했다.
- Route A/B는 실제 `ParcelDelivered` 이벤트와 소포·주소 ID가 일치할 때만 완료된다.
- Route C는 정규 분류 지식으로 봉인을 보존한 채 주소만 복사하거나, 빠르게 봉인을 훼손해 인장으로 사용하는 분기로 나뉜다.
- 서로 다른 주소 조각 2개를 직접 장착한 뒤 별문 손잡이를 당겨야 출항과 심층 보관소가 열린다.
- 메인 통신 기록 일부는 출항 전 필수로, 라니 명령의 전체 맥락은 GateActive 심층 보관소의 선택 진실로 분리했다.
- 희귀 우표와 전체 진실은 반송 불가 보관소를 직접 연 뒤에만 획득할 수 있다.
- CH4 전용 방울 시각 효과, 동적 별문 표지와 플레이테스트 계측을 연결했다.
- 미장착 세 번째 조각이 남은 GateActive 상태에서 잘못된 장착 프롬프트가 나오던 공용 별문 우선순위를 수정했다.

M3-2 내부 검증은 EditMode 테스트 82개 완료·실패 0, C# 컴파일 오류 0,
씬 누락 스크립트 0, 깨진 프리팹 0이다. 실제 씬 스모크에서 Route A/B 배송,
Route C 봉인 보존, 주소 2/2, 수동 GateActive, 메인 기록 출항 차단,
심층 진실, Bell 2, 정상 출항과 여행 티켓 도장을 확인했다.

### M3-3 · CH3 구름고래 목장 별문 이식

- 첫 목장 수차, 폭풍 능선 수차, 구루 강제 기상을 Route A/B/C로 연결했다.
- Route A/B는 실제 구름병 하중 이동과 `CloudRainDock`의 질량·위치 조건을 만족해야 완료된다.
- Route C는 구루 방울 세 번으로 빠르게 완료되지만 피로와 폭풍 피해가 발생한다.
- GateReady 전 자장가 하중 분산 장치로 구루를 다시 재워 Route C의 피해를 수습할 수 있다.
- 구루 닻 해방과 이동식 비구름 장치는 바람 기여 수와 분리된 기존 별도 사건으로 유지했다.
- 시작 시 마루가 길 잃은 새끼 고래를 어미 곁에 돌려놓는 필수 장면을 행동 기록에 추가했다.
- 바람 2/2 뒤 손잡이를 당겨야 출항과 무지개 위쪽 목장이 열리며, 큰 구름병은 입구 선택 뒤에만 획득된다.
- CH3 전용 방울 시각 효과, 동적 별문 표지와 플레이테스트 계측을 연결했다.

M3-3 내부 검증은 EditMode 테스트 92개 완료·실패 0, C# 컴파일 오류 0,
씬 누락 스크립트 0, 깨진 프리팹 0이다. 실제 씬 스모크에서 구름병 하중 이동으로
Route A+B 완료, 바람 2/2, 수동 GateActive, 무지개 목장, 구루 해방과 대체 수차,
Bell 2, 정상 출항과 여행 티켓 도장을 확인했다.

## P0 플레이 루프

1. 달토끼에게 달떡 세 개가 필요하다는 말을 듣는다.
2. 절구의 말로 물건을 크게/작게 바꾼다.
3. 작은 톱니로 방앗간을 고치거나, 흩어진 달떡을 직접 운반한다.
4. 변형을 많이 사용할수록 별냄새가 `고요 → 별내음 → 발자국 → 방울소리 → 돌아갈 시간`으로 상승한다.
5. 네 번째 변형은 과부하를 일으키고 사고 보고서의 인과 사슬에 기록된다.
6. 별 연료 세 개가 모이면 바로 떠나거나, 달 뒤편 창고를 열어 위험을 감수한다.
7. 방울소리 이후 마루가 냄새가 진한 물건과 플레이어를 추적한다. 냄새나는 물건을 내려놓아 유인할 수 있다.
8. 출발 또는 강제 귀가 시 라니가 가장 의미 있는 행동 세 개를 편향되게 기록한다.

## 런타임 모듈

- `StarNightRunState`: 런/챕터/플래그/NPC 상태/후속 결과의 단일 진입점
- `StarNightChapterState`: 출발 진척도와 별냄새 단계
- `FableObject`: 물체 특성, 변형 이력, 물리 상태, 과부하
- `StarNightCombinationResolver`: 도구 적용, 냄새, 행동 기록, 사고 연결
- `StarNightInventory`: 6+2칸 수납과 세계에 남는 드롭
- `StarNightActionRecorder`: 라니 기록 후보와 우선순위
- `StarNightAccidentReportBuilder`: 사고의 원인-결과 문장
- `MaruDirector`: 냄새 기반 경고/추격/유인/강제 귀가
- `StarNightRoomGraphGenerator`: 보장 방과 무작위 곁방의 재현 가능한 그래프
- `StarNightHUD`: 목표, 체력, 냄새, 도구, 가방, 상황 문장, 결말

- 2D Fantasy 프리팹의 시각 요소와 게임 충돌체를 분리해 번들 콜라이더 상태와 무관하게 이동 경로가 안정적으로 유지된다.
- 탐색 구역 25개, 달등불 체크포인트 5개, 추락 복귀를 추가했다.
- 번들 프리팹은 씬 생성 시 완전 언팩하고 깨진 컴포넌트와 불필요한 물리 컴포넌트를 제거한다.

## P1 · 까치다리 정거장

### 핵심 플레이

1. `R`로 절구와 붉은 실을 전환한다.
2. 붉은 실을 든 상태에서 `E`로 첫 물체를 고르고, 다른 물체에 다시 `E`를 눌러 연결한다.
3. 연결된 두 물체는 붉은 실의 수축 길이를 향해 서로를 당기며 힘과 움직임을 나눈다.
4. 실이 지나치게 팽팽해진 상태가 유지되면 끊어지고, 별냄새와 사고 기록이 남는다.
5. 정거장의 세 고정점에 부품을 연결해 까치다리를 복구한다.
6. 까치를 세 번 호출해 강제로 일시키거나, 옛 다리를 끊어 지름길을 여는 선택을 할 수 있다.
7. 해치를 붉은 실로 붙잡거나 물리 레버로 출발문을 잠글 수 있다. 자유를 허용하는 레버도 별도로 존재한다.
8. 별사다리 곁방의 보상을 사용하면 붉은 실 연결 한도가 `3 → 4`로 늘지만 별냄새가 오른다.

### 챕터 전이

- 달토끼 방앗간을 수리했다면 P1의 별냄새 증가량이 15% 감소하고 지원 물자가 실의 내구도를 보강한다.
- 방앗간을 수리하지 않았다면 P1을 별냄새 5와 8% 증가 페널티로 시작한다.
- 달 뒤편 창고를 해결하지 않고 떠나면 추가 별냄새 12와 18% 증가 페널티가 따라온다.
- P1에서 옛 다리를 끊거나 까치를 혹사한 결과는 다음 구름고래 목장의 물자와 구조 지원에 전달된다.

### 라니의 첫 편향

- 해치를 붙잡아 둔 행동은 `안전을 위한 책임`으로 미화한다.
- 해치가 스스로 떠날 수 있게 둔 행동은 `위험한 선택을 방치했다`고 의심한다.
- 플레이어가 다리를 복구해도, 까치가 감당할 장력을 플레이어가 정했다고 기록한다.
- 옛 다리를 끊어 지름길을 만들면 자신의 편의를 위해 물류를 훼손했다고 기록한다.

### P1 씬 구성

- 메인 구역 15개, 별사다리와 옛 다리 지름길 2개 분기
- 물리 붉은 실 고정점 3쌍
- 체크포인트 5개와 독립 충돌 지형
- 2D Fantasy Station, Forest, Crystal, Island 시각 요소
- 해치 선택 구역, 까치 호출 종, 달토끼 지원 상자, 최종 출발문

## P2 · 구름고래 목장

### 구름병의 보존 규칙

1. `R`로 구름병을 선택한다.
2. `E`로 첫 대상의 무게 일부를 병에 담는다. 대상은 질량과 중력이 줄어 떠오른다.
3. 다른 대상에 `E`를 눌러 담긴 무게를 남긴다. 두 대상의 총질량은 변하지 않는다.
4. 첫 대상을 다시 고르면 담긴 무게를 원래대로 돌려놓는다.
5. 한 대상에 지나치게 많은 무게를 몰면 과압과 폭풍 피해가 발생한다.
6. 무지개 위쪽 목장의 큰 병을 얻으면 용량이 `4 → 6`으로 늘지만 별냄새가 크게 오른다.

### 출항 퍼즐과 구루 분기

- 세 하중추에서 무게를 덜어 세 비구름에 옮기고, 무거워진 구름을 아래 수차로 내린다.
- 구루의 방울을 세 번 울리면 즉시 깨어나지만 피로와 폭풍 피해가 누적된다.
- 닻을 풀면 구루는 목장을 떠날 수 있으나 비가 멎기 시작한다.
- 비구름 세 개를 내린 뒤 이동식 수차를 만들면 구루를 다시 묶지 않고 비를 복구한다.
- 강제로 깨우지 않았다면 구루는 새 장치를 보고 스스로 목장으로 돌아온다.

### P1 결과 상속

- 옛 다리를 끊어 둔 경우 P2를 별냄새 8과 10% 증가 페널티로 시작하며 까치 문양 보급고가 빈다.
- 까치를 세 번 강제 호출했다면 별냄새 4와 5% 증가 페널티가 추가되고 폭풍 구조망이 사라진다.
- 두 결과가 함께 남았다면 P2 시작 별냄새는 12가 된다.

### 마루 디렉터 확장

- 기본 냄새 점수에 공중 상태 `+7`, 비구름 `+3` 우선순위를 더한다.
- 공중 목표를 추격할 때 지상 추격보다 빠르게 이동한다.
- 추격 시작 시 최근 사고 보고서의 원인-결과 단계를 순서대로 HUD에 재생한다.
- 가벼운 대상은 마루와 폭풍에 동시에 취약하며, 마루를 무겁게 만드는 선택은 아래 구조물 위험으로 이어진다.

### P2 결과 전이

- 구루를 풀고 비 장치를 복구하지 않으면 별 우체국에 가뭄과 마른 잉크 페널티가 전달된다.
- 폭풍 피해를 수습하지 않으면 젖은 편지와 훼손된 목적지 표식이 전달된다.
- 구루가 자율적으로 돌아오면 비구름 지름길이, 목장을 복구하면 구름 우표 보상이 전달된다.

### P2 씬 구성

- 메인 구역 16개, 무지개 위쪽 목장과 폭풍 아래 회랑 2개 분기
- 총질량이 보존되는 비구름 수차 퍼즐 3개
- 구루의 닻, 강제 기상 방울, 이동식 수차 조립대
- 체크포인트 5개와 양방향 공중 바람 볼륨
- 2D Fantasy Island, Desert, Spring Forest, Crystal, Station 시각 요소

## P3 · 별 우체국

### 별 우표의 주소 규칙

1. `R`로 별 우표를 선택한다.
2. `E`로 소포를 고르면 배송 대기 상태가 되고, 주소가 붙은 사물에 다시 `E`를 눌러 보낸다.
3. 같은 소포를 다시 고르면 빈 우표로 되돌린다.
4. 달·분류실·금고·라니·둥지·북극성 경로의 여섯 주소는 소포뿐 아니라 셀프 우편함을 통한 플레이어 이동에도 쓰인다.
5. 물에 번진 잉크가 남아 있으면 첫 배송이 다른 주소로 갈라지고 사고 보고서가 생성된다.
6. 마른 잉크가 남아 있으면 첫 주소 날인이 실패해 다시 찍어야 하며, 그동안 별냄새가 오른다.

### 마지막 편지와 별길

- 마지막 편지를 봉인한 채 라니에게 배송하면 `STARPATH_LAST_LETTER_DELIVERED`와 북극성 경로 단서가 남고 라니의 통신이 끊긴다.
- 편지를 먼저 열면 경로 단서를 얻지만 라니와의 논쟁 및 다음 챕터 별냄새 페널티가 남는다.
- 편지를 분해하면 강력한 순간이동 코어를 얻는 대신 편지와 직접 별길의 가능성을 파괴한다.
- 편지를 보존하면 지금 당장 내용을 알 수 없지만 봉인된 기억이 다음 챕터의 별냄새를 완화한다.
- 배송 중 추격 상태의 마루는 마지막 편지를 일반 소포보다 `+25` 높은 우선순위로 노린다.

### 분류기 클라이맥스와 전승

- 고장 난 자동 분류기를 과부하하면 소포가 무작위 주소로 연속 배송되어 빠르지만 사고와 별냄새를 만든다.
- 북극성 경로 우표를 회수한 뒤 분류기를 수리하면 안전하게 챕터를 정리할 수 있다.
- P2의 가뭄은 마른 잉크, 미수습 폭풍은 젖은 주소표, 구루의 자율 귀환은 비구름 지름길, 목장 복구는 희귀 구름 우표로 변환된다.
- P3에서 남긴 라니의 침묵·논쟁·순간이동 코어·마루가 훔친 편지·분류기 잔해는 P4 잠든 해의 정원 결과 수정자로 등록된다.

### P3 씬 구성

- 메인 구역 16개, 비구름 지름길과 돌아올 수 없는 반송 금고 분기
- 달·분류실·금고·라니·둥지·북극성 경로의 배송 주소 6개
- 훈련 소포, 셀프 우편함, 마지막 편지의 열기·분해·보존 선택대
- 북극성 경로 우표 회수, 고장 난 자동 분류기의 과부하·수리 결말
- 체크포인트 5개와 2D Fantasy Station, Crystal, Dungeon, Desert, Island 시각 요소

## P4 · 잠든 해님의 정원

### 햇빛 씨앗과 성장 단계

1. 정원 곳곳의 작은 저장 햇빛을 `X`로 모은다.
2. `R`로 햇빛 씨앗을 선택하고 빛 반응 대상에 `E`를 눌러 저장 햇빛 하나를 심는다.
3. 성장 대상은 `휴면 → 각성 → 개화 → 과성장 → 소실`의 단계를 가진다.
4. 개화는 발판·문·생물을 활성화하지만, 과성장은 퇴로를 덮고 소실은 불씨와 사고 기록을 남긴다.
5. 햇빛 사용은 별냄새뿐 아니라 별도의 정원 열을 올린다. 열 70부터 과열, 95부터 화재 상태가 된다.
6. 그늘꽃을 개화시키거나 희귀 햇빛 씨앗을 포기해 정원 열과 타 버린 생물을 수습할 수 있다.

### 해오름과 기다림

- 종에 햇빛 씨앗을 심어 해오름을 즉시 깨우면 별길 나무가 바로 개화하지만 정원 열 `+45`와 큰 별냄새가 발생한다.
- 돌의자에서 세 구역을 기다리면 해오름이 완전한 상태로 스스로 깨어 저장 햇빛 세 개를 제공한다.
- 기다리는 동안 정원의 덩굴과 잠든 생물도 매번 한 단계씩 자라며 정원 열과 별냄새가 오른다.
- 따라서 기다림은 무료 정답이 아니라 생물의 과성장과 마루 도착 시간을 감수하는 선택이다.

### M3-4 · 길꽃 2/2와 수동 별문

- 기본 P4 빌더는 v0.2 공통 별문 루프를 켠다.
- Route A는 지정된 저장 햇빛 세 곳을 실제로 수집해야 `고른 빛`을 만든다.
- Route B는 온실 꼭대기의 반사판을 두 번 조정해야 `높은 빛`과 햇빛 씨앗 하나를 얻고,
  덩굴 과성장·빛나방 기상·귀환 발판 봉쇄를 실제 오브젝트 상태로 남긴다.
- Route C는 씨앗 하나를 소비해 해오름을 강제로 깨워야 `해오름 빛`을 만든다.
- 자연 기상은 해오름과 안정 광원을 보존하지만 강제 기상 Route를 자동 완료하지 않는다.
- 완료된 빛은 자동 적용되지 않으며 별문 허브에 서로 다른 두 개를 직접 장착한다.
- `2/2 GateReady`에서 다시 상호작용해 손잡이를 당겨야 GateActive, 첫 방울, 출구가 열린다.
- 별문 주변 길꽃 두 송이는 실제 장착 수 `0/2`, `1/2`, `2/2`에 맞춰 켜진다.

### 해바라기 너머의 멈춘 방

- GateActive 뒤에도 입구를 직접 선택해야 물리 봉오리 장벽이 열린다.
- 입구 진입은 Alert 12를 남기고, 주머니 해님은 추가 Alert와 정원 열을 발생시킨다.
- 안쪽 보상은 마루의 최초 명령 원본, `STARPATH_MARU_ORIGINAL_COMMAND_KNOWN`,
  `CH5_FINAL_LIGHT_SUPPORT`, 저장 햇빛 두 개다.
- 시작 필수 장면은 마루가 작은 해씨를 돌려놓고 “모두 집으로. 아무도 잃지 않게.”를 반복한 사실을 한 번만 기록한다.
- Bell 1은 꽃의 방향 전환, Bell 2는 빛나는 씨앗 우선 추적, Bell 3은 모든 광원을 잇는 눈길로 표현한다.

### 별길 나무와 결말 (레거시 결과 보존)

- 북극성 별길 나무에 저장 햇빛을 세 번 심으면 관측소행 항로와 출항 조건이 열린다.
- 개화 시점에서 가지를 잘라 안정된 별길을 남기거나, 저장 햇빛을 하나 더 사용해 빠른 과성장 지름길을 만들 수 있다.
- 빛을 계속 겹치면 별길 나무 자체가 타 버려 P5 관측소에 어둡고 끊긴 항로가 전달된다.
- 해바라기 꼭대기의 `주머니 해님`은 저장 햇빛 두 개를 주지만 정원 전체의 식물·적과 마루에게 동시에 빛을 보낸다.
- 추격 중인 마루에게 햇빛 씨앗을 붙이면 약 5초간 눈을 감게 할 수 있지만 별냄새와 열이 크게 오른다.

### P3 결과 상속과 P5 전승

- 열린 편지는 논쟁의 열, 분해한 편지는 순간이동 지름길, 보존한 봉인은 그늘 온실로 변환된다.
- 마루가 편지를 훔쳤다면 편지 냄새의 추적로가, 폭주 분류기를 수리하지 않았다면 가연성 배송 잔해가 생긴다.
- 해오름 자연 기상은 관측소 안정 광원, 강제 기상은 광원 과열 주기로 전달된다.
- 정원 화재 방치는 관측소 기록 소실, 정원 복구는 라니 동생의 화분 연출로 전달된다.
- 안정·과성장·소실한 별길 나무 상태가 P5의 진입 항로와 별냄새 수정자를 결정한다.

### P4 씬 구성

- 저장 햇빛 6개와 정원 진화용 희귀 햇빛 씨앗 1개

- GateActive 전 물리 장벽이 있는 해바라기 너머의 멈춘 방
- 발판 새싹, 잠든 문지기, 나방, 갑충, 그늘꽃, 가연성 덩굴의 성장 대상

- 라니가 시간을 멈춰 둔 동생의 화분과 P3 결과별 환경 흔적
- 체크포인트 5개와 2D Fantasy Spring Forest, Old Forest, Lava, Island, Crystal 시각 요소

M3-4 내부 기준선은 EditMode `102/102`, C# 컴파일 오류 0,

## M4 · 프롤로그, 여행 티켓, 전체 런

### 프롤로그

- `StarNightPrologueBootstrap`이 새 런을 시작하고 프롤로그 목표를 구성한다.
- `PrologueJourneyBeat` 6개가 표지판, 라니 진단, 귀환떡 엔진, 마루 구조,
  길잡이별 소실, CH1 출항을 순서대로 잠근다.
- 귀환떡이 사건을 시작했고, 마루가 우주선을 구조했지만 길잡이별까지 물어와
  다섯 항로를 껐다는 사실을 필수 진행에서 전달한다.
- `Tools > Star Night > Build M4 Prologue`가 12구역의
  `Assets/Scenes/StarNight/StarNight_Prologue.unity`를 생성해 빌드 인덱스 0에 둔다.

### 여행 티켓

- `RunRouteMap`이 5개 별문 도장, 플레이어 위치, 마루 위치와 6개 정거장 이름을 관리한다.
- `TravelTicketPresenter`는 모든 `StarNightHUD`에 런타임 생성된다.
- 프롤로그 목표 공개 뒤부터 `T`로 티켓을 접거나 펼칠 수 있다.
- 도장 갱신 때 마루 표식을 다음 정거장까지 보간한다.
- `RunRouteMapSnapshot`으로 티켓 상태를 직렬화·복원할 수 있다.

### 휴식과 전환

- `JourneyIntermissionFormatter`가 티켓 도장, 행동 되감기, 라니의 문장,
  플레이어 응답, 마루 발자국, 다음 목표의 6단계를 모든 출항 요약에 적용한다.
- CH1 부트스트랩은 프롤로그에서 이어진 활성 런을 초기화하지 않는다.
- CH1~CH4 전환은 공통 `5.2초` 요약 시간을 사용한다.
- 공통 HUD의 GateReady·GateActive 문구는 챕터별 `objectiveNoun`을 사용해
  길떡, 닻, 바람, 주소, 빛을 잘못 섞어 표시하지 않는다.

M4 내부 기준선은 EditMode `114/114`, 프롤로그 씬 검증 문제 0,
누락 스크립트·깨진 프리팹 0, 실제 PlayMode 오류·경고 0이다.

## M5 · 북극성 관측소, 중심별 추격, 네 엔딩

### 관측소 진입과 기록 회랑

- `SunGardenDepartureGate`는 CH5 완료 뒤 런을 종료하지 않고 5.2초 휴식 후
  `StarNight_PolarisObservatory`를 불러온다.
- `PolarisChapterBootstrap`은 다섯 별문 도장 `5/5`를 진입 조건으로 사용한다.
- 에디터에서 관측소를 직접 재생하면 검증용 런과 다섯 도장을 자동 구성한다.
- `PolarisRecordEcho` 5개는 각 챕터의 대표 행동을 중복 없이 기록하고,
  전부 확인해야 `PolarisTruthArchive`가 열리도록 한다.
- 라니의 평가는 사고 기록 유무에 따라 달라지며, 플레이어의 반박은
  이해와 허용을 분리하고 라니가 직접 명령을 거두도록 요구한다.

### 중심별 추격

- `PolarisFinaleState`가 기록 회랑, 관측실, 추격, 최종 선택, 완료를 하나의 상태 머신으로 관리한다.
- 추격은 기본 150초이며 CH5의 자연/강제 기상, 화재·복구,
  별길 나무 상태와 최종 빛 보조를 75~215초 범위로 환산한다.
- 마루는 이전 행동 기록에서 가장 자주 사용한 도구를 역이용 대상으로 표시한다.
- 복구 순서는 `Resize → Link → Float → Deliver → Awaken`으로 고정하며
  순서를 건너뛴 입력은 상태를 바꾸지 않는다.
- 시간 초과는 마루의 중심별 선점을 기록하고 `ClosedUniverse`를 즉시 확정한다.

### 네 엔딩과 별길 조건

- `PathCutter`, `NewLeash`, `ClosedUniverse`, `StarRoad`를
  `PolarisEndingChoice` 월드 상호작용으로 선택한다.
- 별길은 기억·연결·배송·빛 네 묶음을 모두 만족해야 한다.
- 마지막 편지를 파괴했다면 라니 명령의 전체 맥락과 보존된 동생 화분을
  함께 발견한 경우에만 대체 기억으로 인정한다.
- 별길 성공은 `POLARIS_RANI_DELIVERED`, `POLARIS_MARU_RELEASED`를 남기고,
  최종 행동을 `RaniCommandWithdrawn`, 런 종료 사유를 `JourneyComplete`로 기록한다.
- `StarNightHUD.ShowFinalEnding`은 일반 챕터 휴식 포맷을 거치지 않고
  최종 엔딩 본문과 여행 완료 문구를 표시한다.

### 씬 구성과 에디터

- `Tools > Star Night > Build M5 Polaris Observatory`가 2D Fantasy 아트를 사용한
  23구역 가로형 관측소를 생성하고 CH5 다음 빌드 항목에 둔다.
- 대표 기록 5개, 생활 도구 복구 5개, 엔딩 선택 4개, 체크포인트 6개,
  중심별과 마루 추격 표현을 포함한다.
- `PolarisFinalePresenter`는 현재 목표, 남은 시간, 마루의 역이용 도구,
  별길 네 조건을 화면에 표시한다.
- `PolarisInheritedDisplay`는 CH5의 안정 광원, 과열, 화재·복구,
  별길 나무 세 상태를 관측소 환경으로 다시 보여 준다.

M5 내부 기준선은 EditMode `132/132`, C# 컴파일 오류 0,
씬 검증 문제·누락 스크립트·깨진 프리팹 0이다.
실제 PlayMode에서 기록 5개, 진실 확인, 도구 복구 5단계,
별길 엔딩과 `RaniCommandWithdrawn`까지 확인했다.

## M6 · 밸런스 프로파일, 전체 런 계측, 회귀 감사

### 밸런스 기준과 전체 런 표본

- `StarNightBalanceProfile`이 일반 `45~60분`, 별길 `60~80분`,
  유혹 진입 `55~70%`, Route 최소 선택률 `10%`를 소유한다.
- 7개 챕터 시간 예산과 5개 별문 챕터의 Route ID를 코드 기준으로 제공한다.
- `StarNightRunTelemetry`가 챕터 경계를 넘어 시간, Route 장착, 유혹 진입,
  최고 방울, 종료 Alert, 엔딩, 정보량, 사고 Gate/Bell 문맥을 모은다.
- `StarNightTelemetryStore`는 정상 완료 PlayMode 런만 PlayerPrefs에 누적하며
  관측소 직접 실행과 디버그 스모크는 제외한다.

### 방울 압박 재조정

- GateActive 즉시 첫 방울, 수동 행동이 없어도 `90초` 두 번째,
  `180초` 세 번째 방울로 진행한다.
- 냄새 감소는 다음 방울까지 시간을 벌지만 이미 울린 방울을 되돌리지 않는다.
- 세 번째 방울은 Alert `60`과 GateClosing을 유지한다.
- 사고 보고서의 각 단계가 당시 Gate/Bell 상태를 저장해 결과 문장에 표시한다.

### QA 도구와 씬 안정성

- `Tools > Star Night > Run M6 Balance & Regression Audit`가 빌드 순서,
  밸런스 상수, Route 프로파일, 7개 씬 무결성과 핵심 상호작용을 검사하고
  `docs/star-night/M6_AUTOMATED_QA_REPORT.md`를 생성한다.
- 북극성 씬의 다중 MonoBehaviour 파일을 클래스별 파일로 분리해
  도메인 리로드 시 상호작용이 `NULL`로 역직렬화되던 문제를 제거했다.
- Moon Mill, 구름고래 목장, 별 우체국의 현재 폰트 미지원 화살표 글리프를 교체했다.
- Unity 6 권장 `Physics2D.OverlapCircle`/`ContactFilter2D`와
  TMP `textWrappingMode` API로 이전했다.

M6 내부 기준선은 EditMode `158/158`, 자동 구조 감사 `25/25`,
Moon Mill과 북극성 PlayMode 오류·경고 `0`이다.
사람 플레이 표본은 아직 `0런`이며,
일반 5세션과 별길 5세션을 완료하기 전에는 시간·선택률 목표를 확정하지 않는다.
